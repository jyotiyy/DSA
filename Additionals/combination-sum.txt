# 1D DP: FORWARD vs BACKWARD ITERATION

## Core Idea

In many 1D DP / Knapsack problems, the direction in which we iterate over the DP array determines whether the current item can be used multiple times or only once.

--------------------------------------------------
1. DP STATE
--------------------------------------------------

dp[s] = all combinations that can make sum s
        using the candidates processed so far.

Base case:

dp[0] = {{}}

Reason:
There is exactly one way to make sum 0:
choose nothing.

--------------------------------------------------
2. UNLIMITED USE OF AN ITEM
--------------------------------------------------

If an item/candidate can be used MULTIPLE TIMES:

    for (int s = x; s <= target; s++)

Use FORWARD iteration.

Why?

Suppose x = 2.

First:

    dp[2] ← dp[0] + 2
    dp[2] = [2]

Then while continuing forward:

    dp[4] ← dp[2] + 2
    dp[4] = [2,2]

Then:

    dp[6] ← dp[4] + 2
    dp[6] = [2,2,2]

Therefore:

    dp[0]
      ↓
    dp[2]
      ↓
    dp[4]
      ↓
    dp[6]

The newly created state can immediately be used again.

Therefore:

    FORWARD = ITEM CAN BE REUSED


--------------------------------------------------
3. USE AN ITEM ONLY ONCE
--------------------------------------------------

If an item/candidate can be used ONLY ONCE:

    for (int s = target; s >= x; s--)

Use BACKWARD iteration.

Suppose x = 2.

We process:

    target → ... → 2

When calculating a larger sum, dp[s-x] has NOT yet been
updated using the current x.

Example:

    s = 4

We check:

    dp[4-2] = dp[2]

But dp[2] has not yet been created during the current
iteration because we haven't reached s = 2.

Therefore the current 2 cannot be used again.

Eventually:

    s = 2

We create:

    dp[2] ← dp[0] + 2

But all larger states have already been processed.

Therefore this newly created dp[2] cannot be reused.

Hence:

    BACKWARD = ITEM CAN BE USED ONLY ONCE


--------------------------------------------------
4. WHY FORWARD CAUSES REUSE
--------------------------------------------------

Example:

    x = 2

Forward:

    s = 2
    dp[2] = [2]

    s = 4
    dp[4] uses dp[2]

But dp[2] was created using the CURRENT 2.

Therefore:

    [2] → [2,2]

Then:

    s = 6
    dp[6] uses dp[4]

Therefore:

    [2,2] → [2,2,2]

So forward iteration allows:

    2
    ↓
    2 + 2
    ↓
    2 + 2 + 2
    ↓
    ...

--------------------------------------------------
5. WHY BACKWARD PREVENTS REUSE
--------------------------------------------------

Example:

    x = 2

Backward:

    s = 7
    s = 6
    s = 5
    s = 4
    s = 3
    s = 2

When we calculate dp[4]:

    dp[4] uses dp[2]

But dp[2] has NOT been updated using the current 2 yet.

So [2,2] cannot be created.

Only later, when we reach s = 2:

    dp[2] = dp[0] + 2

But we have already passed s = 4.

Therefore the new dp[2] cannot be used again.

--------------------------------------------------
6. THE GOLDEN RULE
--------------------------------------------------

    Can use item multiple times?
                ↓
             FORWARD

    for (int s = x; s <= target; s++)


    Can use item only once?
                ↓
             BACKWARD

    for (int s = target; s >= x; s--)


--------------------------------------------------
7. COMBINATION SUM CONNECTION
--------------------------------------------------

Unlimited reuse:

    for (int x : candidates) {
        for (int s = x; s <= target; s++) {
            ...
        }
    }

Forward iteration allows:

    [2]
    [2,2]
    [2,2,2]
    ...

Therefore candidates can be reused.


If each candidate can be used only once:

    for (int x : candidates) {
        for (int s = target; s >= x; s--) {
            ...
        }
    }

Backward iteration prevents the current candidate from
being used again.

--------------------------------------------------
8. EASY WAY TO REMEMBER
--------------------------------------------------

FORWARD:

    Newly created state
           ↓
    can be used immediately
           ↓
    REUSE ALLOWED


BACKWARD:

    Newly created state
           ↓
    all relevant states already processed
           ↓
    REUSE NOT ALLOWED


--------------------------------------------------
9. INTERVIEW ONE-LINER
--------------------------------------------------

"Forward iteration allows the current item to contribute
to states that are processed later, so the item can be
used multiple times.

Backward iteration ensures that the current item cannot
be reused within the same iteration, so it is used at most
once."


--------------------------------------------------
10. MOST IMPORTANT PATTERN
--------------------------------------------------

UNBOUNDED / UNLIMITED KNAPSACK:

    for (s = x; s <= target; s++)
        // FORWARD


0/1 KNAPSACK:

    for (s = target; s >= x; s--)
        // BACKWARD


MEMORIZE:

    FORWARD  → REUSE
    BACKWARD → USE ONCE




    # Combination Sum IV — Why Is the Sum Loop Outside?

## 1. Problem Requirement

In Combination Sum IV:

* We can use each number unlimited times.
* **Order matters.**

For example:

```text
nums = [1, 2]
target = 3
```

These are different:

```text
[1, 2]
[2, 1]
```

Therefore, we must count different **sequences**, not just combinations.

---

## 2. DP State

```cpp
dp[s]
```

means:

> Number of different ordered sequences that can form sum `s`.

Base case:

```cpp
dp[0] = 1;
```

There is one way to make sum `0`:

```text
[]
```

---

## 3. Recurrence

To calculate `dp[s]`, think:

> What number can be placed at the END of the sequence?

If `x` is the last number:

```text
previous sum = s - x
```

Therefore:

```cpp
dp[s] += dp[s-x];
```

For every possible `x`:

```cpp
for(int s = 1; s <= target; s++) {
    for(int x : nums) {
        if(s >= x)
            dp[s] += dp[s-x];
    }
}
```

---

# 4. Why Is the SUM Loop Outside?

The important point is:

```cpp
for(int s = 1; s <= target; s++)       // OUTSIDE
{
    for(int x : nums)                  // INSIDE
    {
        dp[s] += dp[s-x];
    }
}
```

We calculate the states in increasing order:

```text
dp[0]
 ↓
dp[1]
 ↓
dp[2]
 ↓
dp[3]
 ↓
...
dp[target]
```

When calculating `dp[s]`, all smaller states:

```text
dp[0], dp[1], ..., dp[s-1]
```

have already been calculated.

This allows every possible number to become the **last element** of the sequence.

---

# 5. Example

```text
nums = [1,2]
target = 3
```

### Calculate dp[1]

Possible last number:

```text
1
```

So:

```text
dp[1] = dp[0] = 1
```

Sequence:

```text
[1]
```

---

### Calculate dp[2]

Possible last numbers:

```text
last = 1
→ previous sum = 1
→ dp[1]

last = 2
→ previous sum = 0
→ dp[0]
```

Therefore:

```text
dp[2] = dp[1] + dp[0]
      = 1 + 1
      = 2
```

Sequences:

```text
[1,1]
[2]
```

---

### Calculate dp[3]

Possible last numbers:

```text
last = 1
→ dp[2]

last = 2
→ dp[1]
```

Therefore:

```text
dp[3] = dp[2] + dp[1]
      = 2 + 1
      = 3
```

Sequences:

```text
[1,1,1]
[1,2]
[2,1]
```

Notice:

```text
[1,2] ≠ [2,1]
```

Both are counted.

---

# 6. What If We Put the Candidate Loop Outside?

Suppose we write:

```cpp
for(int x : nums) {
    for(int s = 1; s <= target; s++) {
        if(s >= x)
            dp[s] += dp[s-x];
    }
}
```

Now we process:

```text
1 completely
↓
then 2 completely
↓
then 3...
```

This creates a fixed candidate-processing order.

It naturally counts combinations rather than all possible orderings.

For:

```text
nums = [1,2]
target = 3
```

it can count:

```text
[1,1,1]
[1,2]
```

but does not independently generate:

```text
[2,1]
```

So this loop order is **not suitable when order matters**.

---

# 7. The Key Difference

## Combination Sum — order does NOT matter

```cpp
for(int x : nums) {
    for(int s = x; s <= target; s++) {
        ...
    }
}
```

Think:

> Process each candidate and build combinations using it.

Therefore:

```text
[1,2] = [2,1]
```

---

## Combination Sum II — each item once

```cpp
for(int x : nums) {
    for(int s = target; s >= x; s--) {
        ...
    }
}
```

Backward iteration prevents the same item from being reused.

Therefore:

```text
FORWARD  → reuse allowed
BACKWARD → use once
```

---

## Combination Sum IV — order DOES matter

```cpp
for(int s = 1; s <= target; s++) {
    for(int x : nums) {
        ...
    }
}
```

Think:

> For this particular sum `s`, what number can be placed LAST?

Therefore:

```text
[1,2] ≠ [2,1]
```

---

# 8. Most Important Mental Model

### If ORDER MATTERS:

```text
SUM → CANDIDATE
```

```cpp
for(sum)
    for(candidate)
```

Because for every sum, we consider **every possible last element**.

---

### If ORDER DOES NOT MATTER:

```text
CANDIDATE → SUM
```

```cpp
for(candidate)
    for(sum)
```

Because we process candidates in a fixed order and don't create different permutations.

---

# 9. Quick Memory Trick

```text
Combination Sum:
Candidate → Sum
Order doesn't matter
Forward sum
Reuse allowed

Combination Sum II:
Candidate → Sum
Order doesn't matter
Backward sum
Use once

Combination Sum IV:
Sum → Candidate
ORDER MATTERS
Forward sum
Reuse allowed
```
